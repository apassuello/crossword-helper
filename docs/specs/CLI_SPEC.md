## Overview

**[SPEC]**
The CLI (`cli/src/cli.py`) is the single source of truth for all crossword
construction logic. It exposes 14 commands via a Click group. The Flask
backend calls these commands via subprocess; it adds no business logic of
its own. See `docs/specs/BACKEND_SPEC.md` for the subprocess integration
layer and `docs/ARCHITECTURE.md` for the full system diagram — neither is
duplicated here.

**[NOTE]**
This document covers command *usage*: arguments, options, and verified
output shapes. It intentionally does not describe internal algorithm
pseudocode, data-structure internals, or performance figures — those go
stale the moment the implementation changes and cannot be checked by a
reader running the CLI. A previous version of this file contained
implementation code referencing `StateManager.load_state` and
`GridFiller.from_state`; neither method exists anywhere in the codebase.
That code has been removed rather than corrected — see the changelog.

### `fill`

**[SPEC]**
```bash
crossword fill [GRID_FILE] -w/--wordlists PATH [...] [OPTIONS]
```

`grid_file` is optional (only) when `--resume` is given.

| Option | Type | Default | Notes |
|---|---|---|---|
| `--wordlists`, `-w` | Path, multiple | required unless `--resume` state recorded its own | — |
| `--timeout`, `-t` | int | `300` | Seconds. `repair` and `hybrid` reject values &lt;10 with an error and exit `1` |
| `--min-score` | int | `30` | 1–100 |
| `--algorithm`, `-a` | Choice `regex`\|`trie`\|`beam`\|`repair`\|`hybrid` | **`repair`** | See note below |
| `--beam-width` | int | `5` | Beam search / hybrid |
| `--output`, `-o` | Path | overwrites `grid_file` | — |
| `--allow-nonstandard` | flag | off | — |
| `--json-output` | flag | off | Progress → stderr, result → stdout |
| `--attempts` | int | `1` | Randomized restart attempts |
| `--theme-entries` | Path | none | JSON, see [Theme Entries Format](#theme-entries-format) |
| `--theme-wordlist` | Path | none | Wordlist to prioritize |
| `--adaptive` | flag | off | Auto-place black squares when stuck |
| `--max-adaptations` | int | `3` | — |
| `--partial-fill` | flag | off | Stop when stuck instead of aggressive backtracking, keeping ≥80% valid words |
| `--cleanup` | flag | off | After fill, remove invalid words while keeping letters shared with valid crossings |
| `--task-id` | string | none | Enables `crossword pause TASK_ID` on this run |
| `--resume` | Path (or bare task id) | none | Continues a paused fill; see the resolution note below |

**[NOTE]** The Click default for `--algorithm` is `repair`, not `hybrid`. A
caller that omits `-a` believing it gets the "hybrid" behavior described in
older documentation is silently running iterative repair instead.

```bash
python -m cli.src.cli fill puzzle.json -w data/wordlists/comprehensive.txt -t 10 --min-score 30
```

**[SPEC] `fill --resume` state resolution.** `fill --resume` no longer delegates
to the `resume` command's implementation — it continues the fill in-process so
exact-position CSP resume is reachable. It resolves its argument the same way
`resume` does, so both accept the same forms: an existing file path is loaded
from its own directory; otherwise the value is a bare task id looked up in
`--state-dir` (or the StateManager default, which is what `resume` always uses).
`<id>`, `<id>.json` and `<id>.json.gz` are all accepted. `-w` wins for
wordlists, falling back to the paths recorded in the saved state.

**[NOTE] Known limitation — exact-position resume does not make progress**
when the saved partial assignment was already a dead end: the run returns
immediately with `success: false` and no additional slots filled. `_resume_fill`
continues from the saved position and does not unwind a contradictory
assignment, so a branch that was doomed when the pause landed stays doomed.
Measured on `feature/m1-constructors-bench` alone before the merge — same
result — so it predates the merge. Tracked as
[issue #9](https://github.com/apassuello/crossword-helper/issues/9); the fix is
to wire `_unwind_dead_ends` into `_resume_fill`. Pinned by
`backend/tests/integration/test_cli_integration.py::TestResumeCLIInvocationReal::test_pause_then_fill_with_resume`
(`time_elapsed > 0.5`), whose guard is `xfail`ed on that assertion alone until
#9 closes.

**[SPEC] Verified JSON result fields** (stdout, `--json-output`):
`success`, `grid`, `slots_filled`, `total_slots`, `fill_percentage`,
`time_elapsed`, `iterations`, `problematic_slots_count`, `all_slots_filled`,
`paused`, `task_id`, `wordlists`, `output_file`, `suggestions` (present on
partial/problematic fills), `state_path` (present when `paused` is true and a
state was written). Progress updates are streamed to stderr as
`{"progress": N, "message": "...", "status": "running"|"complete"}` lines.

**[SPEC] Exit codes**

| Code | Meaning |
|---|---|
| `0` | The solver ran and produced a result — **including a partial or unsuccessful fill** |
| `1` | The run could not happen or could not finish: missing grid file, unreadable wordlist, invalid theme entries, out-of-range `--timeout` |

- A caller must never infer fill quality from the exit code. Parse the JSON
  `success` field for that. A grid the solver could not complete is a result,
  not an error.
- This is deliberate, not an oversight. `backend/core/cli_adapter.py` raises
  `CalledProcessError` on any non-zero exit, and the web UI renders a partial
  fill as a normal outcome; exiting non-zero on an unsuccessful fill would turn
  that outcome into an error at the seam.
- Pinned by `cli/tests/unit/test_fill_command.py`. Reproduce with:

      pytest cli/tests/unit/test_fill_command.py

**[SPEC] `--timeout` has a 10-second floor under `repair` and `hybrid`**
- `iterative_repair.py`'s `fill()` rejects a timeout below 10 seconds. The CLI
  reports this as a normal error and exits `1`; with `--json-output` the error
  is returned as `{"success": false, "error": ...}` on stdout.
- Pass `-t 10` or higher. `beam` and the classic algorithms have no such floor.

**[NOTE]** `repair` (and therefore the default run) can report
`all_slots_filled: true` together with `success: false` — every slot has a
letter, but some crossing words are not valid dictionary words
(`problematic_slots_count > 0`). Check both fields, not just one.

### `analyze`

**[SPEC]**
```bash
crossword analyze GRID_FILE -w/--wordlists PATH [...] [--word TEXT --slot "row,col,direction,length"] [--json-output]
```

Two modes:
- **No `--word`**: per-cell constraint counts (how many wordlist entries
  fit each open slot).
- **`--word` + `--slot`** (both required together): impact of placing that
  word in that slot on every crossing slot's remaining candidate count.

```bash
python -m cli.src.cli analyze puzzle.json -w data/wordlists/comprehensive.txt --json-output
python -m cli.src.cli analyze puzzle.json -w data/wordlists/comprehensive.txt --word OCEAN --slot "0,0,across,5" --json-output
```

**[SPEC] Verified JSON shapes:**
```json
// no --word
{"constraints": {"4,0": {"across_options": 1865, "down_options": 1865, "min_options": 1865}, "...": "..."}}

// with --word/--slot
{"impacts": {"0,0,down": {"before": 1865, "after": 47, "delta": -1818, "length": 11}, "...": "..."},
 "summary": {"total_crossings": 5, "worst_delta": -1829, "crossings_eliminated": 0},
 "success": true}
```

### `pause`

**[SPEC]**
```bash
crossword pause TASK_ID [--json-output]
```

Signals a currently-running `fill --task-id TASK_ID` process to save its
state and exit at the next checkpoint. `TASK_ID` must belong to a fill
that is actually running with that `--task-id` — pausing an unknown or
already-finished task fails.

```bash
python -m cli.src.cli pause nonexistent_task --json-output
```
```json
{"success": false, "task_id": "nonexistent_task",
 "error": "Task 'nonexistent_task' is not running (start a fill with --task-id nonexistent_task first)"}
```
Exit code `1` on this failure (verified live).

**[SPEC]** Mechanism: creates a flag file at
`/tmp/crossword_pause_{task_id}.flag`; the running `fill` process polls for
this file (via `PauseController`) and, on detecting it, serializes its
state and exits. See [Pause/Resume Workflow](#pauseresume-workflow).

## Grid File Format

**[SPEC]**
```json
{
  "size": 11,
  "grid": [
    [".", ".", "#", "A", "..."],
    ["...", "...", "...", "...", "..."]
  ]
}
```
Cell values: `.` = empty, `#` = black square, `A`–`Z` = filled letter.
Verified against a live `new` + `number` round trip.

### Theme Entries Format

**[SPEC]** JSON object mapping a `"(row,col,direction)"` string key to the
word to lock in that slot:
```json
{"(0,1,across)": "OCEAN", "(7,5,down)": "ANNIVERSARY"}
```
Parsing tolerates spaces after commas (`"(0, 1, across)"`) and either quote
style around the tuple parts; a malformed key is skipped with a warning
(human mode) rather than aborting the run. Verified by reading the parser
in `cli.py` (`fill`'s `--theme-entries` handling).

## Wordlist File Format

**[SPEC]** `WordList.parse_line()` (`cli/src/fill/word_list.py`) accepts,
per line:

| Format | Example | Score |
|---|---|---|
| Plain | `CAT` | computed from letter frequency |
| Semicolon-scored | `CAT;50` | taken from file, overrides computed score |
| Comma-scored | `cat,50` | taken from file, overrides computed score |

`data/wordlists/comprehensive.txt` is plain-format (one word per line, no
scores) — confirmed by inspection. A malformed scored line (e.g. a CSV
header row) is skipped, not treated as a word.

**[NOTE]** An earlier version of this document described a fixed TSV
`WORD\tSCORE\tSOURCE` format. That format is not what `parse_line()`
implements and has been removed rather than corrected.

## Pause/Resume Workflow

**[SPEC]**
1. Start a fill with a task id: `crossword fill grid.json -w list.txt --task-id mytask`.
2. From another terminal: `crossword pause mytask`. This creates
   `/tmp/crossword_pause_{task_id}.flag`; the running fill polls for it via
   `PauseController` and, on the next checkpoint, serializes its state and
   exits.
3. State is written to `/tmp/crossword_states/{task_id}.json.gz` (or
   `.json` if uncompressed) — **not** the `/tmp/autofill_state_{task_id}.json`
   path an earlier version of this document described; that path does not
   exist anywhere in `state_manager.py` or `pause_controller.py`.
4. `crossword list-states` shows what's saved.
5. `crossword resume mytask` continues from the saved position, using the
   wordlists/algorithm recorded in the state unless overridden with
   `-w`/`-a`.

**[?]** No environment variable overrides either the pause-flag directory
(fixed at `/tmp`) or the state directory (fixed at `/tmp/crossword_states`)
— confirmed by `grep -rn "environ\|getenv" cli/src/` returning no matches.
If a `--state-dir` or `--pause-flag-dir` CLI flag is expected to exist,
it does not: neither appears in any of the 14 commands' `--help` output.

## Algorithm Selection

**[NOTE]** `-a`/`--algorithm` on `fill` and `resume` accepts `regex`,
`trie`, `beam`, `repair`, or `hybrid`:

- `regex` / `trie` — classic CSP backtracking; `trie` is the faster pattern
  matcher of the two. Guaranteed to find a solution if one exists within
  the domains explored, at the cost of speed on large grids.
- `beam` — maintains multiple candidate grids in parallel (`--beam-width`),
  optimizing for word quality; no completeness guarantee.
- `repair` — fills fast, then iteratively replaces conflicting words;
  **this is the default**. Can finish with all cells filled but some
  crossing words invalid — check `problematic_slots_count`.
- `hybrid` — runs beam search, then falls back to repair on what's left
  unfilled.

For actual speed/success-rate comparisons on your grids and wordlists, run
the algorithm and read its own reported `time_elapsed`/`iterations` — this
document does not assert benchmark numbers, since they depend on grid,
wordlist, and machine.

## Known Issues

**[SPEC]** The two entries previously listed here are no longer defects. `fill`
exiting `0` on an unsuccessful fill is the intended contract — see **Exit
codes** above — and a sub-10-second `--timeout` now produces a normal CLI error
instead of a traceback.

**[SPEC] `--theme-entries` preserves theme words.** A `slow`-marked canary
(`backend/tests/integration/test_theme_priority.py::TestThemeEntriesCLICanary`)
long asserted the opposite; its fixture asked the flag to place a 3-letter
entry into a 5-letter slot, so the CLI rejected the entry and the run ended
before locking. Fixed and confirmed to discriminate — with the flag the fill
preserves the entry, without it the solver overwrites the cells. Note that
each entry's length must match its slot exactly, or `fill` errors and exits `1`.

**[?]** Whether `pause`/`list-states`/`resume` behave correctly for tasks
started via the *backend* (as opposed to a bare `crossword fill --task-id`
invocation) was not re-verified for this rewrite — see
`docs/specs/BACKEND_SPEC.md` for the backend's own pause/resume contract.
